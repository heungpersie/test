# 데이터 접근·보관·삭제 정책 설계 v1

2026-11-05 · 기준 1의 데이터 수명주기 설계 초안. 실행 코드·S3 lifecycle rule·DB migration을 추가하거나 실제 데이터를 삭제하지 않았다.

확정 기반: 3분 영상, 비동기 분석, 화면 이탈 후 조회, 자동 재시도, RDS PostgreSQL·S3. 아래 저장 경로·권한·보관 정책은 검토안이다. **보관 일수·삭제 기한·보고서 유지 여부는 아직 팀 승인 전이며 운영 기본값으로 적용하지 않는다.**

## 1. 데이터 흐름과 공통 원칙

원본 업로드 → 음성/프레임 추출 → 전사·특징량 → 점수·보고서·Q&A 생성 → 사용자 조회 → 만료/삭제 요청 → 접근 차단·작업 중단 → 실제 정리 → 완료 기록.

- 모든 원본·파생 데이터에 같은 소유자·프로젝트·회차·analysisId를 연결하고 분석 attempt·모델 버전·목적을 추적한다. attempt별 임시 산출물은 다른 attempt와 섞지 않는다.
- 수집·접근은 승인된 목적과 범위에 한정한다. 분석 동의는 전문가 평가·외부 LLM 전송·학습 활용 동의를 자동 대체하지 않는다.
- dev와 demo에는 별도 데이터·권한을 사용한다. 개발에는 합성/사용 허락된 샘플을 우선하며 실사용자 영상을 무단 복제하지 않는다.
- 기본은 비공개 저장이다. 식별자·S3 경로를 안다는 이유만으로 권한을 부여하지 않는다. BE가 소유권·동의·삭제·만료를 확인한 뒤 필요한 객체만 접근시킨다.
- 이름 비식별화가 영상·얼굴·음성·전사 내용의 익명화를 의미하지 않는다. 암호화는 보관·권한·삭제 정책을 대신하지 않는다.

## 2. 데이터별 정책표

기간 기호는 승인 후 설정할 값이며 현재 확정 숫자가 아니다. 기산점·종료 조건을 함께 지정한다.

| 데이터 | 저장 위치 제안 | 접근 주체·목적 | 보관 기준안 | 삭제 범위·완료 기준 |
|---|---|---|---|---|
| 원본 영상 | 비공개 S3 originals/ | 본인: BE 발급 URL, AI: 작업 처리. 전문가는 별도 동의·배정 시만 | 업로드 완료 시각부터 R_ORIGINAL. 기존 API의 30일은 승인 전 예시 | 현재/과거 버전·복제본·캐시·다운로드 임시본 정리. 보고서 유지 여부 별도 결정 |
| 업로드 조각·미완료 객체 | S3 staging/; multipart는 채택할 때만 | 업로드 주체·완료 검증 BE·정리 작업 | upload expiry 이후 R_STAGING. 유효 업로드·검증 중 작업 제외 | 임시 객체 정리, multipart 도입 시 미완료 업로드 abort까지 확인 |
| 추출 음성 | AI 임시 디스크, 재사용 필요 시만 S3 derived/ | 해당 AI 작업만. 사용자·운영자 기본 열람 없음 | 정상 종료 후 R_TEMP 내 정리, 재시도 중은 승인된 재사용 기간까지 | 작업 디렉터리·S3 사본·개발자 수동 복사본 포함 |
| 얼굴·영상 프레임 | 메모리/스트리밍 우선, 필요 시 임시 디스크 | 시선·표정 분석 AI만 | 추출/분석에 필요한 최소 시간. 저장 예외에만 R_TEMP | 메모리 작업 종료·디스크/객체/캐시 제거. 운영 로그·리포트에 원본 프레임 미포함 |
| 전사문·문장 타임스탬프 | 비공개 S3 또는 RDS 중 BE·AI 계약으로 결정 | 해당 AI·필요한 BE 처리. 본인 화면 제공 범위는 제품 결정 | 보고서 생성 후 R_TRANSCRIPT. 원본과 별도 만료 설정 가능 | 원문·분할 문장·인덱스·프롬프트 캐시·외부 제공 사본 추적 |
| 특징량·타임라인 | S3 derived/ + RDS 메타데이터 | AI·BE·본인 리포트 표시 범위 | 분석 완료 후 R_FEATURE. 원본과 연결된 개인정보로 취급 | 버전별 산출물·DB 참조·표시용 캐시 정리 |
| 분석 보고서·점수 | RDS 참조/조회 데이터 + S3 reports/ | 본인·필요 BE. 운영자는 기본 내용 열람 금지 | 완료 후 R_REPORT. 원본 만료 후 유지 여부 별도 승인 | DB 내용·객체·내보낸 파일·비교/이력 캐시. 삭제한 보고서가 재생성되지 않음 |
| Q&A·코칭 문구 | 보고서의 qa가 정본, 저장 상세는 BE 계약 | 본인·AI·필요 BE. 전문가 기본 접근 없음 | 부모 보고서의 기간 이하. 별도 Q&A 연장 금지 제안 | 최신/이전 생성본·LLM 입력/출력 캐시·리포트의 중복 사본 포함 |
| 라이브 미저장 recap·임시 조각 | 필요한 범위 RDS/S3 임시 영역 | 본인·복원 처리 BE | undoUntil까지 접근, 이후 R_STAGING 내 정리. 30초는 기존 명세 예시 | 되살리기와 만료·삭제 경합 방지, 세대별 조각 제거 |
| 동의·삭제 처리 증거 | 제한된 RDS 메타데이터/별도 기록 저장소 | 권한 있는 담당자·BE 처리 | 목적·증빙 필요에 따른 R_EVIDENCE. 승인 근거와 만료 필요 | 원본·내용을 증거로 무기한 보관하지 않음. 최소 식별자·정책 버전·처리 결과만 |
| 작업 상태·attempt 이력 | RDS analysis metadata | 본인 상태 조회·BE/AI·제한된 장애 대응자 | 작업 종결 후 R_JOB. 재시도/중복 방지 기간을 포함 | 오류 원문·민감 입력 제거, 사용자 삭제 후 남길 최소 범위 결정 |
| 백업·스냅샷·복제본 | 암호화 RDS backup·S3 version/replica·승인된 백업 | 복원 담당자만, 일상 조회 금지 | 각 복사본 생성부터 R_BACKUP. live 데이터 보존 기간과 별도 승인 | 잔여 복사본 만료 추적, 복원 시 삭제 이력 재적용. 개별 데이터 즉시 삭제 보장으로 오인 금지 |

운영·감사 로그는 별도 감사 설계에서 저장 위치·보관 기간·열람 권한을 구체화한다. 로그에 원본 영상·음성·프레임·전사·Q&A 본문을 넣어 우회 보관하지 않는다.

## 3. 역할별 접근 요약

| 주체 | 허용 | 기본 금지 |
|---|---|---|
| USER | 자기 영상/리포트·Q&A·진행 상태, 자기 삭제 요청 | 타인 객체·raw 프레임·DB 직접 접근 |
| BE runtime | 소유권 확인·URL 발급·접수/조회/삭제 제어 | 모든 버킷 관리·IAM 변경·무관한 환경 데이터 |
| AI worker | 현재 작업 원본 읽기·임시 추출·산출물 쓰기 | 임의 사용자 전체 열람·자기 판단으로 보관 연장 |
| EXPERT | 별도 활용 동의·유효 배정의 영상·평가 입력 | 전사·보고서·Q&A·AI 점수·타 배정, 관리자 역할만으로 우회 |
| ADMIN/운영 | 서비스 상태·제한된 메타데이터·최소 장애 증거 | 원본·전사 상시 열람. 예외는 사유·승인·종료·감사 기록 필요 |
| 삭제/복원 담당 | 승인된 범위 정리·복원·검증 | 무관한 사용자/환경 삭제·복원 데이터 즉시 공개 |

S3 권한은 environment·객체 범위·필요 action으로 제한하고 사용자별 접근은 BE에서 다시 검증한다. S3 전체 삭제 권한을 일반 AI 역할에 주지 않는다. Compose 컨테이너별 AWS 역할 격리의 제약은 [네트워크·보안 설계](NETWORK_SECURITY.md)를 따른다.

## 4. 기간 설정·변경 규칙

- retentionExpiresAt은 승인한 정책 버전·기산점·기간으로 서버에서 계산한다. 만료 판단은 서버 UTC 기준이며 화면만 KST로 표시한다.
- R_TEMP·R_STAGING은 정상 처리/재시도/검증 완료 조건을 함께 보고 계산한다. 단순 파일 나이만으로 실행 중 입력을 지우지 않는다. heartbeat 유실·고아 작업은 lease/timeout 규칙으로 판정한다.
- 원본만 만료된 경우와 사용자 회차/계정 전체 삭제를 구분한다. 전자는 승인한 범위에서 파생 리포트 유지 가능, 후자는 대상 파생물 전체를 추적한다.
- 자동 재시도·Q&A 재생성은 보관 시계를 무조건 갱신하지 않는다. 원본과 기존 데이터의 기한을 넘어가면 재사용/재시도를 거부하거나 승인 정책을 적용한다.
- 기간 변경은 정책 버전·승인·기존 데이터 적용 방식·기한 단축 안내·비용 영향을 기록한다. 운영자가 만료일을 임의 연장하지 않는다.
- 숫자 미승인 상태에서 실사용자 데이터를 받아 무기한 저장하지 않는다. 제한된 테스트 데이터·승인된 시험 기간과 종료 정리 계획으로 검증한다.

## 5. 삭제 요청·철회·만료 처리

다음은 구현할 내부 처리 단계 제안이며 현재 API enum이나 DB 테이블에 구현됐다는 뜻이 아니다.

1. 요청자·소유권·범위 확인: 영상만/회차 전체/계정/동의 목적 철회를 구분하고 요청 ID를 발급한다.
2. 즉시 논리 차단: 신규 조회·서명 URL 발급·평가 배정·분석/LLM 전송을 막고 삭제 표식을 커밋한다. 만료도 같은 접근 차단 원칙을 적용한다.
3. 실행 중 작업 통제: 취소 또는 결과 공개 차단. 실행 전·업로드 후·결과 DB 커밋 시 삭제 표식을 재확인한다. 늦게 돌아온 worker·재시도 결과가 삭제 데이터를 복구하지 못하게 한다.
4. 원본·파생 정리: 객체 manifest와 연결 관계로 영상·음성·프레임·전사·특징량·보고서·Q&A·attempt 임시본·인덱스를 식별해 정리한다. 삭제 작업 자체는 멱등적으로 재실행한다.
5. 복사본 처리: S3 과거 버전·복제·백업·외부 LLM 제공 사본의 범위와 남은 기한을 기록한다. Object Lock/별도 보존 제약이 있다면 즉시 완료로 표시하지 않는다.
6. 완료 검증: 사용자 조회/URL 접근·객체 버전·DB 참조·늦은 작업 결과를 확인한다. 일부 실패는 pending으로 남기고 재시도·담당자 확인 대상으로 표시한다.
7. 최소 증거 기록: 요청/대상 식별자·정책 버전·접수/차단/정리/완료 시각·실패 코드·잔여 사본 범위. 삭제한 원문을 증거로 다시 저장하지 않는다.

삭제 API 응답 성공, 접근 차단 완료, 온라인 원본/파생 삭제, 백업 만료를 별도 상태로 구분한다. 최종 SLA와 사용자에게 보여줄 표현은 제품·BE·인프라 합의 후 결정한다. 기존 기능에 되살리기 기간이 있으면 그 기간 내 논리 폐기와 되돌릴 수 없는 물리 삭제가 동시에 성공하지 않도록 한다.

이미 발급한 서명 URL은 DB 표식만으로 무효화되지 않는다. 객체/버전 제거·접근 정책 차단·캐시 제어와 URL TTL을 함께 검토하고 기존 URL 접근 거부를 실제 시험한다. 클라이언트가 이미 내려받은 사본까지 원격 삭제했다고 주장하지 않는다.

## 6. S3 lifecycle·버전·임시 디스크

- S3 lifecycle은 오래된 객체 정리 보조 수단이며 사용자의 즉시 삭제·동의 철회를 대신하지 않는다. 정확한 사용자 기한은 BE/정리 작업이 제어하고 lifecycle 적용 지연을 완료 SLA로 가정하지 않는다.
- Versioning 사용 시 일반 DELETE가 delete marker만 만들 수 있다. 현재/과거 version과 delete marker를 구분해 정리하고 필요한 s3:DeleteObjectVersion 권한을 전용 정리 역할에만 준다. marker만 제거해 과거 데이터가 다시 보이지 않게 한다.
- 복제 사용 시 목적 버킷/버전·삭제 복제 설정을 확인한다. 원본 삭제만으로 복제본 정리가 끝났다고 판단하지 않는다.
- 미완료 multipart 정리는 도입 시 lifecycle abort 규칙을 별도로 구성한다. 현재 API 명세는 multipart 도입을 확정하지 않았으므로 이를 구현 완료로 표시하지 않는다.
- 프레임·음성은 메모리·스트리밍 우선. tmpfs는 메모리 상한·OOM 영향을 검토하고 디스크 임시본은 암호화 EBS·작업별 디렉터리로 제한한다. 앱의 정상 종료 정리 외에 비정상 종료·재부팅 후 고아 파일 정리도 필요하다.

## 7. 백업·복원과 외부 LLM

백업에서 특정 사용자의 행을 즉시 개별 제거하기 어려울 수 있다. 접근을 제한하고 승인된 백업 기한까지 추적하되 삭제 완료 표현을 구분한다. 백업 기한 미정은 무기한 보관 허용이 아니다.

복원은 격리 환경에서 수행하고 외부 접속·worker·알림을 먼저 차단한다. 삭제 요청/철회 이력의 최신 사본을 복원 DB와 별도로 확보해 재적용하고, 원본·파생 manifest와 만료를 재검증한 뒤 서비스에 연결한다. 오래된 백업으로 삭제 표식까지 되돌려 데이터가 재공개되는 것을 방지한다.

외부 LLM/Bedrock 선택 전 제공 지역·전송 내용·업체 보관·학습 이용·삭제 요청·계약 조건을 확인한다. 우리 저장소 삭제가 제공자 사본 삭제를 의미하지 않는다. 업체 설정·삭제 응답·만료 등 확인 가능한 범위를 기록한다. 사용자의 원본·전사·보고서·Q&A를 별도 승인 없이 학습/보정 데이터로 사용하지 않는다. 이미 승인된 보정·평가 집합은 참조와 정책을 추적하고 철회 시 제외/재계산 범위를 AI팀과 결정한다.

## 8. 구현 책임·검증 계획

| 담당 영역 | 구현·합의할 일 | 시험 근거 |
|---|---|---|
| BE | 소유권·동의·기한·삭제 표식·API·manifest 연결·최종 결과 커밋 차단 | 타인 ID·기한 경계·동시 삭제/complete/retry·리포트/영상 분리 |
| AI | 작업별 임시본·원문 최소화·삭제/취소 확인·늦은 결과 거부 협조 | 처리 도중 삭제·강제 종료·재시도와 삭제 경합 |
| Infra | 비공개 S3/IAM·암호화·정리 실행 환경·백업/복원·고아 파일 처리 | 원본·버전·복제본·임시 디스크 정리와 복원 재공개 방지 |
